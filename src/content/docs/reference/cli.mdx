The `asciichem` CLI provides conversion, linting, identity, resolution,
citation, and round-trip verification. Install via `gem install asciichem`.

The full command list is also one keystroke away:

```sh
asciichem help              # the command list
asciichem help convert      # options for one command
asciichem tree              # compact command tree
```

## convert

Convert AsciiChem source to an output format.

```sh
asciichem convert -i "H_2O" -t mathml
asciichem convert -i "2Na+ + SO_4^2- -> Na_2SO_4" -t cml
asciichem convert -f input.asciichem -t html
echo "H_2O" | asciichem convert -i - -t latex
```

### Options

| Flag | Description |
|---|---|
| `-i, --input` | Source text (or `-` for stdin) |
| `-f, --file` | Read source from a file |
| `-t, --format` | Output format: `mathml` (default), `text`, `html`, `latex`, `svg`, `structural-svg`, `model-json`, `cml`, `smiles`, `molfile` |
| `--from` | Input grammar: `asciichem` (default), `smiles`, `molfile` |
| `--engine` | Parsing engine: `parslet` (default), `parsanol`, `parg` — see below |

### Parsing engines

`--engine` selects the parsing engine for that invocation:

- `parslet` — the default. Pure Ruby, zero extra dependencies.
- `parsanol` — opt-in Rust-backed engine over the same grammar and
  transform (needs the `parsanol` gem); absent gem exits 6 with
  install guidance.
- `parg` — opt-in engine over the compiled PARG grammar artifact
  (the same checksummed artifact [asciichem-rs](/implement/rust/)
  runs; needs parsanol ≥ 1.3.94).

```sh
asciichem convert -i "2H_2 + O_2 -> 2H_2O" -t text --engine parsanol
```

The `ASCIICHEM_ENGINE` environment variable selects the engine for
programmatic use and test runs (`parslet`, `parsanol`, or `parg`).

### Input grammars

Since 0.22.0, `convert` selects the input grammar with `--from asciichem|smiles|molfile`,
and the output targets include `model-json`, `smiles`, `molfile`, and `structural-svg`:

```sh
asciichem convert -i "CCO" --from smiles -t structural-svg
asciichem convert -f ethanol.mol --from molfile -t model-json
asciichem convert -i "CC(=O)OC1=CC=CC=C1C(=O)O" --from smiles -t smiles   # canonical re-emission
```

Every grammar funnels into the one semantic model, so every output
format works regardless of input language. Molfile input may be a
file path (multiline text via `-f`).

## resolve

Resolves an identifier into a substance record from one resolver
source (networked; cached in your user cache directory with a 7-day
TTL). Give exactly one of `--cas`, `--name`, `--cid`, `--inchikey`,
or `--smiles`:

```sh
asciichem resolve --name aspirin --source pubchem -t model-json
asciichem resolve --cas 50-78-2 --refresh            # bypass the cache
asciichem resolve --cas 50-78-2 --source common_chemistry -t smiles
```

`--source` picks the source (`pubchem` is the default; `opsin`
answers IUPAC names, `common_chemistry` answers CAS numbers), and
`-t` picks the output (`model-json`, `text`, or `smiles`). Every
result carries per-identifier provenance including the source's
required attribution. In the library, all shipped sources are on by
default and resolved together — see
[Structures and resolution](/guides/structures-and-resolution/).

## cite

Resolves an identifier and emits a dataset-type Relaton bibitem
(XML) for the source it was resolved from — the same code path the
Metanorma plugin uses, so a document and the command line can never
disagree:

```sh
asciichem cite --cas 50-78-2
# <bibitem id="PubChemCID2244" type="dataset"> …
```

Options match `resolve` (`--cas/--name/--cid/--inchikey/--smiles`,
`--source`, `--refresh`). One bibitem per (substance, source); the
field-by-field shape is on
[Citing substances](/guides/citing-substances/).

## validate

Offline validation of identifier annotations in a formula:

```sh
asciichem validate -i 'H_2O @cas("7732-18-5")'
# cas          7732-18-5                                ok
```

## identity

Derives InChI and InChIKey from the structure itself — offline, via
the configured InChI engine (the IUPAC `inchi-1` binary or the
native Rust engine; the InChI algorithm is never reimplemented):

```sh
asciichem identity -i "CC(=O)OC1=CC=CC=C1C(=O)O" --from smiles
# InChI=1S/C9H8O4/c1-6(10)13-8-5-3-2-4-7(8)9(11)12/h2-5H,1H3,(H,11,12)
# BSYNRYMUTXBXSQ-UHFFFAOYSA-N

asciichem identity -i "..." --engine-bin /usr/local/bin/inchi-1
```

`--from` selects the input grammar (`asciichem`, `smiles`, or
`molfile`); the formula must contain exactly one molecule.
`--engine-bin` points at an `inchi-1` binary for this invocation.
Without any engine the command exits 5 with install guidance — see
[Local identity](/reference/identity/) for every engine option,
including the native Rust engine driven through `CHEMOMER_LIB`. In
Ruby, register one globally:

```ruby
AsciiChem::Inchi.engine = AsciiChem::Inchi::BinaryEngine.new
AsciiChem::Inchi.identity_for(molecule)
```

With an engine configured, `asciichem lint` cross-checks `@inchi` and
`@inchikey` annotations against the drawn structure
(`IdentityCrossCheck`).

## lint

Run chemistry validation checks. Exits 1 if any errors found.

```sh
asciichem lint -i "H_2 + O_2 -> H_2O"
asciichem lint -i "crystal[x](a=-1){Na@f(0,0,0)}" -f json
```

### Options

| Flag | Description |
|---|---|
| `-i, --input` | AsciiChem source text |
| `-f, --format` | Output format: `text` (default) or `json` |

JSON output is an array of `{severity, message, node}` objects. The
checks behind it are on the [Linter](/reference/linter/) page.

## roundtrip

Parse and re-emit text; exit non-zero if output differs from input.

```sh
asciichem roundtrip -i "H_2O"
```

## parse-cml

Parse CML XML and emit AsciiChem text.

```sh
asciichem parse-cml -i "<cml xmlns=\"http://www.xml-cml.org/schema\">...</cml>"
```

## version

```sh
asciichem version
asciichem --version   # or -v
```

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Success (also: `lint` clean, `validate` with no invalid identifiers) |
| 1 | Parse error; `lint` found errors; `roundtrip` mismatched; `validate` found an invalid identifier |
| 2 | Unknown output format (`convert -t`) |
| 3 | Resolve error (unknown source, no answer) |
| 4 | Cite error |
| 5 | Identity error (including no engine configured) |
| 6 | Parsing engine unavailable (`--engine parsanol`/`parg` without the gem) |
