An implementation's conformance claim is a **level**, not a vibe. The
levels are cumulative: claiming L(n) means L(0..n−1) hold too. Every
claim is gated in the implementation's own CI by the
[shared corpus](/models/#conformance) — fixtures are data, never edited
to make an implementation pass — and a level claim without the green
corpus run behind it does not ship.

## The syntax contract

L0 is defined against a grammar contract, not against the reference
parser's observed behaviour. The single source of truth for the syntax
is [asciichem-parg](https://github.com/asciichem/asciichem-parg): the
complete AsciiChem grammar as a committed PARG text contract,
`grammar/asciichem.parg` (sha256
`a94cfb4f59936a381e9974e8c141c661e56a25babe46d64b0a288bfd0b4b3e3d`).

The PARG compiler ([parsanol](https://github.com/parsanol/parsanol-ruby),
pinned by ref in the contract repo's CI) compiles the contract to a
checksummed artifact whose envelope carries the source hash and the
compiler version; `parsanol parg check` compares both and exits
non-zero on a stale artifact, so an implementation cannot silently
parse a different language than the contract. Implementations vendor
the artifact from the contract repo. The copies vendored by the Ruby
reference (`lib/asciichem/engine/parg/asciichem.json`) and
[asciichem-rs](https://github.com/asciichem/asciichem-rs)
(`artifacts/asciichem.json`) are byte-identical (sha256
`b5c1f5289f0487e974091e451f5b2703c12c861347c09dd8332bdcfd1822c34f`),
and their embedded source hash matches the committed grammar.

The contract repo's CI enforces two suites: the grammar's inline
acceptance tests, and corpus parity — the parse/reject fixtures of the
shared corpus (227 at the time of writing) behave identically under
the PARG artifact.

## The levels

**L0 — Notation.** The text syntax parses and canonicalizes. Every
construct the implementation accepts round-trips through the canonical
text form (`parse(to_text(m)) == m` for every model the implementation
can represent), rejection is clean (the implementation's parse-error
type, never a crash), and acceptance is the PARG contract's
acceptance — not a dialect of it.

**L1 — Semantics.** The parse is a string → model mapping, not
typography: isotopes bind atoms (`^14C` →
`Atom(element: "C", isotope: "14")`, never a phantom `{}` carrier),
charges and oxidation states are typed fields, bond kinds and
directions are model data, reactions carry roles, stoichiometry, and
conditions. The semantic model is checked against the corpus's
canonical wire form, and emission validates against the
[asciichem-model v1](/models/) JSON Schemas.

The **perception pass** is part of L1: chemistry the syntax leaves
implicit is derived once, as model services, and every implementation
must derive the same values. Today that covers implicit hydrogens
(aromatic bonds order 1.5 for H-counting, so `c1ccccc1` and
`C1=CC=CC=C1` perceive one hydrogen per carbon; a non-integral or
over-valent sum yields *no answer* rather than an invented one) and
aromatic rings (six-membered, fused-system sp2 rule; five-membered
rings are a documented limitation). The shared corpus pins both —
including the declines.

**L2 — Render.** The model renders deterministically: MathML
byte-identical against the corpus goldens, canonical text, and the
wire form for every construct the implementation represents. SVG
(typographic and structural) is rendered byte-exactly across
implementations against committed reference snapshots.

**L3 — Stereo.** Tetrahedral parity (`@`/`@@` → TH1/TH2), directional
bonds (`/`, `\` → up/down), wedge/hash depiction semantics. Stereo
survives every round-trip (text, SMILES, wire, CML), enantiomers and
diastereomers stay distinct through the canonical form, and canonical
SMILES emits parity-correct tokens.

**L4 — Identity.** The model resolves to authoritative identity:
InChI/InChIKey via the opt-in engine, identifier cross-validation
(`@inchi`/`@smiles`/`@cas` checked against the structure), and
citation-grade resolution — one bibitem per (substance, source) the
author chose, with per-identifier provenance.

## How the corpus gates each level

Each formal level is demonstrated by a set of named gates in the
corpus manifest (`suite.yaml`):

| Level | Corpus gates | Fixtures |
|---|---|---|
| L0 notation | `parse/reject` (parses or rejects exactly as marked); `L1` (canonical Text round-trip) | parser-acceptance, fuzz-corpus |
| L1 semantics | model equality against the canonical wire form; `L0` (emission validates against the v1 schemas); `CML` (three-way round-trip) | parser-acceptance `model` fields, perception, cml-roundtrip |
| L2 render | `L2` (byte-identical MathML goldens); text goldens; cross-implementation SVG snapshots | mathml |
| L3 stereo | stereo cases inside the parse, round-trip, and structure gates — including the declines | parser-acceptance (stereo), smiles (chirality, E/Z direction, enantiomer pairs), molfile |
| L4 identity | `identifiers` (format-level validation only — assignment checking is resolution, not conformance); `linter` (diagnostics match expectations) | identifiers, linter-expectations, inchi-tests (oracle corpus, separate repo) |

One naming caveat: the corpus manifest historically names some *gates*
`L0`, `L1`, `L2` (schema-valid emission, Text round-trip, MathML
goldens). Those are gate names, not the formal levels. The numbering
on this page is the claim language; a formal claim of L(n) is
demonstrated by the gate set in the table above, not by matching
numbers.

## Current claims

Claims are pinned to what each implementation's CI actually runs —
every implementation pins the corpus at a tag (currently **v0.8.0**)
and bumps the pin deliberately, one line per corpus release.

| Level | Ruby (reference) | TypeScript | Python | Rust |
|---|---|---|---|---|
| L0 notation | **yes** | **yes** (100%) | **yes** (100%) | **yes** — parses the PARG artifact; canonical text |
| L1 semantics | **yes** | **yes** (100%; wire round-trip lossless for the core set — beyond-core node types are emission-only) | **yes** (100%) | **yes** (100%; model subset mirrors the reference TransformRules — out-of-subset constructs report unsupported, never guessed) |
| L2 render | **yes** | **yes** — canonical text, wire, MathML goldens, typographic + structural SVG | **yes** — canonical text, wire, MathML goldens, SVG byte-exact with TS | **yes** — MathML goldens and SVG byte-exact with TS |
| L3 stereo | **yes** — chirality, directional bonds, wedge/hash; parity-correct canonical SMILES including ring closures | **yes** (100%) — chirality, directional bonds, parity-correct canonical SMILES | **yes** (100%) — chirality, directional bonds | **yes** — chirality, directional bonds, Hückel perception, canonical aromatic SMILES (asciichem-rs#17; the molfile stereo-code gate lands with interchange, rs#10) |
| L4 identity | **yes** — opt-in InChI engine (binary or native) with stereo layers, OPSIN adapter, identifier cross-check, resolver (PubChem, OPSIN, and Common Chemistry registered by default — attributed; `sources:` limits the set), citation bibitems | engine seam only (`identityFor` over a registered engine); no bundled engine — not claimed | engine seam only (`asciichem.inchi`); no bundled engine — not claimed | **engine in-process** — chemomer as a pinned crate dependency, the full oracle family (5,627 fixtures) gated byte-exact (asciichem-rs#18); resolver and citation land with rs#13/#14 |

Notes:

- The native InChI engine is its own project
  ([chemomer/chemomer](https://github.com/chemomer/chemomer)), gated by
  the [inchi-tests](https://github.com/chemomer/inchi-tests) oracle
  corpus (pinned at v0.3.41). It is reachable from Ruby through the
  `NativeEngine` and from JavaScript and Python through its C ABI and
  bindings; it is not an asciichem-rs claim.
- L4 resolution defaults: PubChem (keyless PUG-REST), OPSIN, and CAS
  Common Chemistry are all registered by default (the CC BY-NC 4.0
  default-on is the maintainer's source-selection call of 2026-11-11);
  every record and bibitem carries the source's required attribution,
  and callers limit the set explicitly (`sources:`, or the plugin's
  `asciichem-sources` attribute) when a document must stay NC-free.
