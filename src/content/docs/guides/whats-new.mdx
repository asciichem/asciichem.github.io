The v0.2x line turns AsciiChem from a parser into a chemistry
platform: external structures flow in, identities resolve, and three
independent implementations pass the same corpus.

<CardGrid stagger>
  <Card title="Structure interchange" icon="right-arrow">
    SMILES and molfile (V2000) ingest into the semantic model — the
    same tree the AsciiChem syntax produces — so database chemistry
    renders, lints, and serialises unchanged. Deterministic SMILES
    re-emission round-trips aspirin exactly. See
    [Structures and resolution](/guides/structures-and-resolution/).
  </Card>
  <Card title="Resolution with provenance" icon="seti:default">
    `AsciiChem::Resolver` turns identifiers into substance records —
    multi-source, cross-checked, cached in the user cache dir, with
    per-identifier provenance. PubChem first; more sources opt-in.
    CLI: `asciichem resolve --cas 50-78-2`.
  </Card>
  <Card title="Three implementations, one contract" icon="seti:json">
    TypeScript (`asciichem`) and Python (`asciichem-py`) joined the
    Ruby reference, all passing the same shared corpus — the
    single-contract rule. See [Implementations](/implement/).
  </Card>
  <Card title="Local identity: the InChI engine" icon="seti:search">
    Derive InChI/InChIKey from the drawn structure, offline — the
    IUPAC `inchi-1` binary behind an opt-in engine, never a
    reimplementation. `@inchi` annotations are cross-checked against
    what you actually drew. CLI: `asciichem identity -i ... --from
    smiles`. See [Structures and
    resolution](/guides/structures-and-resolution/).
  </Card>
  <Card title="MathML parity, byte for byte" icon="seti:json">
    The corpus grew an L2 level: MathML goldens from the reference
    implementation, compared as exact strings. All three
    implementations — Ruby, TypeScript, Python — now emit identical
    MathML; the playground shows it live. Stereo markers survive the
    wire form. Embedded math crosses through the
    [mml](https://github.com/plurimath/mml) contract model — typed
    parse and framework re-serialize, not xpath surgery.
  </Card>
  <Card title="Shareable playground links" icon="external">
    The live renderer writes its state into the URL fragment
    (`#code=…&lang=…&mode=…`). Open a playground link and land on the
    same expression, language, and output mode.
  </Card>
  <Card title="Opt-in Rust-core parsing engine (0.29.0)" icon="seti:rust">
    The same grammar and transform now run over
    [Parsanol](https://github.com/parsanol/parsanol-ruby)'s Rust-backed
    parslet-compat layer: `AsciiChem::Engine.use(:parsanol)` — the
    full spec suite passes identically under either engine, at ~2.4×
    parse speed. Parslet stays the default; parsanol is an opt-in soft
    dependency.
  </Card>
  <Card title="The contract is not a package" icon="seti:folder">
    asciichem-model is now a pure contract repository: LUTAML
    definitions, v1 schemas, generated types. Implementations vendor
    from tags; nothing depends on a gem. See [The wire form](/models/).
  </Card>
  <Card title="v0.2 foundations" icon="seti:rust">
    Reaction cascades, the linter framework, stereochemistry prefixes,
    all bond kinds, Greek letters, fuzzing and benchmarks — see the
    [syntax pages](/syntax/).
  </Card>
</CardGrid>
