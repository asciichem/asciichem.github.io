The v0.2x line turns AsciiChem from a parser into a chemistry
platform: external structures flow in, identities resolve, and three
independent implementations pass the same corpus.

<CardGrid stagger>
  <Card title="Structure interchange" icon="right-arrow">
    SMILES and molfile (V2000) ingest into the semantic model — the
    same tree the AsciiChem syntax produces — so database chemistry
    renders, lints, and serialises unchanged. Deterministic SMILES
    re-emission round-trips aspirin exactly. See
    [Structures and resolution](/guides/structures-and-resolution/).
  </Card>
  <Card title="Resolution with provenance" icon="seti:default">
    `AsciiChem::Resolver` turns identifiers into substance records —
    multi-source, cross-checked, cached in the user cache dir, with
    per-identifier provenance. PubChem first; more sources opt-in.
    CLI: `asciichem resolve --cas 50-78-2`.
  </Card>
  <Card title="Three implementations, one contract" icon="seti:json">
    TypeScript (`asciichem`) and Python (`asciichem-py`) joined the
    Ruby reference, all passing the same shared corpus — the
    single-contract rule. See [Implementations](/implement/).
  </Card>
  <Card title="The contract is not a package" icon="seti:folder">
    asciichem-model is now a pure contract repository: LUTAML
    definitions, v1 schemas, generated types. Implementations vendor
    from tags; nothing depends on a gem. See [The wire form](/models/).
  </Card>
  <Card title="v0.2 foundations" icon="seti:rust">
    Reaction cascades, the linter framework, stereochemistry prefixes,
    all bond kinds, Greek letters, fuzzing and benchmarks — see the
    [syntax pages](/syntax/).
  </Card>
</CardGrid>
