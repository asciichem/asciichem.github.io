The v0.2x line turns AsciiChem from a parser into a chemistry
platform: external structures flow in, identities resolve, and three
independent implementations pass the same corpus.

<CardGrid stagger>
  <Card title="Structure interchange" icon="right-arrow">
    SMILES and molfile (V2000) ingest into the semantic model — the
    same tree the AsciiChem syntax produces — so database chemistry
    renders, lints, and serialises unchanged. Deterministic SMILES
    re-emission round-trips aspirin exactly. See
    [Structures and resolution](/guides/structures-and-resolution/).
  </Card>
  <Card title="Resolution with provenance" icon="seti:default">
    `AsciiChem::Resolver` turns identifiers into substance records —
    multi-source, cross-checked, cached in the user cache dir, with
    per-identifier provenance. PubChem first; more sources opt-in.
    CLI: `asciichem resolve --cas 50-78-2`.
  </Card>
  <Card title="Three implementations, one contract" icon="seti:json">
    TypeScript (`asciichem`) and Python (`asciichem-py`) joined the
    Ruby reference, all passing the same shared corpus — the
    single-contract rule. See [Implementations](/implement/).
  </Card>
  <Card title="Local identity: the InChI engine" icon="seti:search">
    Derive InChI/InChIKey from the drawn structure, offline — the
    IUPAC `inchi-1` binary behind an opt-in engine, never a
    reimplementation. `@inchi` annotations are cross-checked against
    what you actually drew. CLI: `asciichem identity -i ... --from
    smiles`. See [Structures and
    resolution](/guides/structures-and-resolution/).
  </Card>
  <Card title="MathML parity, byte for byte" icon="seti:json">
    The corpus grew an L2 level: MathML goldens from the reference
    implementation, compared as exact strings. All three
    implementations — Ruby, TypeScript, Python — now emit identical
    MathML; the playground shows it live. Stereo markers survive the
    wire form. Embedded math crosses through the
    [mml](https://github.com/plurimath/mml) contract model — typed
    parse and framework re-serialize, not xpath surgery.
  </Card>
  <Card title="Shareable playground links" icon="external">
    The live renderer writes its state into the URL fragment
    (`#code=…&lang=…&mode=…`). Open a playground link and land on the
    same expression, language, and output mode.
  </Card>
  <Card title="Chemistry in Metanorma documents" icon="seti:default">
    The [`metanorma-plugin-asciichem`](https://github.com/metanorma/metanorma-plugin-asciichem)
    gem closes the document loop: `[chem]` blocks render as MathML
    formulas in any Metanorma flavour, and `@cite`-annotated molecules
    resolve into dataset-type bibliography entries — one per
    (source, substance), anchored by InChIKey — collected
    automatically into the References section. See [Chemistry in
    Metanorma](/guides/metanorma/).
  </Card>
  <Card title="Opt-in Rust-core parsing engine (0.29.0)" icon="seti:rust">
    The same grammar and transform now run over
    [Parsanol](https://github.com/parsanol/parsanol-ruby)'s Rust-backed
    parslet-compat layer: `AsciiChem::Engine.use(:parsanol)` or
    `asciichem convert --engine parsanol` — the full corpus passes
    identically under either engine (221/221 re-verified against
    parsanol 1.3.27, all four reported upstream issues fixed), at
    ~2.6× parse speed. Parslet stays the default; parsanol is an
    opt-in soft dependency.
  </Card>
  <Card title="The contract is not a package" icon="seti:folder">
    asciichem-model is now a pure contract repository: LUTAML
    definitions, v1 schemas, generated types. Implementations vendor
    from tags; nothing depends on a gem. See [The wire form](/models/).
  </Card>
  <Card title="Stereo end to end (L3)" icon="seti:default">
    Tetrahedral chirality (`@`/`@@`) and directional E/Z bonds are
    model data through text, SMILES, and wire; canonical SMILES emits
    parity-correct tokens including ring closures, and chirality
    crosses into InChI as MDL atom parity. See [the levels
    spec](/guides/conformance-levels/).
  </Card>
  <Card title="Reactions as semantics (0.31.x)" icon="seti:default">
    Typed condition roles (`[cat: Pd; solv: THF]`),
    `Reaction#stoichiometry` as model data feeding the balance check,
    a derived mechanism step graph (catalysts, inter-step links, and
    electron-flow markers), and RInChI keys through the opt-in engine. See [Reaction
    conditions](/syntax/reactions/#structured-role-entries) and
    [Mechanism](/model/mechanism/).
  </Card>
  <Card title="The perception pass" icon="seti:default">
    One shared chemistry-perception layer — implicit hydrogens that
    decline rather than invent, and Hückel aromaticity counting
    (furan, pyrrole, and thiophene perceived from Kekulé bond orders)
    — conformance-tested through the corpus so every implementation
    derives the same values. The linter consumes it; the canonicalizer
    requires it. See [Perception](/guides/perception/).
  </Card>
  <Card title="Canonical aromatic SMILES" icon="seti:json">
    The SMILES writer now consumes the perception pass: Kekulé input
    canonicalizes to the lowercase aromatic form (`[nH]` for pyrrole
    nitrogen), deterministically, with corpus fixtures pinning the
    exact output. See [Canonical form](/guides/canonical-form/).
  </Card>
  <Card title="The identity loop, closed" icon="seti:search">
    OPSIN resolves IUPAC names to structures, identifier cross-checks
    compare sources, and citations resolve per (substance, source) —
    with the sources settled: PubChem default, CAS Common Chemistry
    opt-in under its CC BY-NC terms, attributed. See [Citing
    substances](/guides/citing-substances/).
  </Card>
  <Card title="Native InChI, no binary at runtime" icon="seti:rust">
    The Rust engine derives the full standard identifier — canonical
    numbering, mobile-H groups, stereo layers, and the InChIKey with
    a dependency-free SHA-256 — gated 1559/1559 against the recorded
    oracle corpus. It ships as a Rust library, a C ABI, and
    Python/WASM/Node bindings; the Ruby gem reaches it through
    `AsciiChem::Inchi::NativeEngine`. See
    [Identity](/guides/structures-and-resolution/).
  </Card>
  <Card title="Four implementations, every gated level" icon="seti:rust">
    The Rust core completes the set: wire, canonical text, MathML
    goldens, and SVG byte-exact across renderers — and Python's SVG
    matches TypeScript byte for byte. Every implementation holds L0
    through L3, and CI consumes the corpus and model schemas pinned
    to released tags. See [Implementations](/implement/).
  </Card>
  <Card title="v0.2 foundations" icon="seti:rust">
    Reaction cascades, the linter framework, stereochemistry prefixes,
    all bond kinds, Greek letters, fuzzing and benchmarks — see the
    [syntax pages](/syntax/).
  </Card>
</CardGrid>
