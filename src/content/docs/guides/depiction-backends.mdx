Structural SVG has two independent halves: **where atoms sit** and
**how they are drawn**. AsciiChem owns the drawing (bonds, labels,
stereo marks) and delegates placement to a *depiction backend*, so a
stronger layout engine can be plugged in behind the model without
touching the renderer.

<LiveRenderer initial="C1-C-C-C2-C-C-C2-C-C1" />

The renderer above places the fused ring system live: perceived rings
draw as regular polygons, fused rings fit rigidly onto their shared
atoms (placed atoms never move), and chains grow as standard-angle
zigzags — the chemistry-shaped placement every runtime ships.

## Placement across the runtimes

All four implementations read the same model; placement is a view,
so each runtime's renderer speaks the same three-tier posture:

1. **Authored coordinates first.** When every atom carries `x2`/`y2`
   (a CML round-trip or a molfile ingest preserves them), the layout
   uses them verbatim — the molecule's own geometry wins, no placer
   runs. Partial authoring is ignored (the placer takes over).
2. **The depiction placer.** Rings as regular polygons (fused rings
   anchored on their shared atoms, spiro centres oriented away from
   the placed region), chains as ±60° alternating zigzags grown
   breadth-first, deterministic collision-avoiding substituent
   placement. TypeScript and Python use it as their built-in
   placement; the Ruby gem exposes it opt-in:
   `AsciiChem::Layout.layout(molecule, algorithm: 'depiction')`.
3. **The layered layout** (Ruby's default). The elkrb Sugiyama
   layering stays the reference implementation's default — the
   determinism the visual-regression goldens depend on.

## Stereo depiction: the wedge synthesis

A structure that carries tetrahedral parity but no authored wedge
bonds — every SMILES-ingested stereocentre, `@smiles("C[C@H](O)N")` —
draws **one synthesized wedge/hash** so the enantiomers render as
distinguishable drawings:

<LiveRenderer initial={'@smiles("C[C@H](O)N")'} />

The model's parity (`TH1`/`TH2`, the SMILES `@`/`@@`) is defined
against the reference ligand order — the stated hydrogens first, then
the neighbours in bond order — and the synthesized glyph realizes that
hand against the drawn neighbour geometry: the wedged ligand rises out
of the plane (a hash sinks it), the stated hydrogen sits at the
tetrahedral completion opposite the drawn neighbours, and the
wedge/hash choice is the one whose 3D orientation matches the parity.
Synthesis **declines rather than guesses** — an atom whose ligand set
is not tetrahedral, with no claimable plain single bond, or with a
degenerate (zero-volume) drawn geometry renders exactly as without
synthesis; authored wedge/hash bonds stay verbatim and are never
doubled. The same fitted core drives the molfile writer's wedge
emission, where the drawn hand and the wedge code must agree or an
engine reading the file derives the mirror enantiomer.

The acceptance is corpus-gated, not asserted: the shared corpus's
depiction family pins the enantiomer pairs' rendered bytes (opposite
parities must draw differently), the molfile-write family pins the
writer's bytes, and the identity batteries derive each enantiomer's
recorded oracle InChI from its own drawing — the drawn hand is
proven, not eyeballed.

## The backend contract (Ruby)

A backend responds to `layout(molecule, algorithm:)` and returns a
`Layout::Result`:

```ruby
class MyBackend
  def layout(molecule, algorithm: 'layered')
    AsciiChem::Layout::Result.new(
      atoms: [AsciiChem::Layout::PositionedAtom.new(
        id: 1, element: 'C', x: 10.0, y: 20.0
      )],
      bonds: [],
      width: 100.0, height: 100.0
    )
  end
end
```

Positions are plain numbers in the drawing's coordinate space; the
renderer scales to the SVG viewport. Atom `id`s must match the ids the
walker assigns, exactly as the built-in pipeline does.

## When to plug in another

- A heavier depiction engine (RDKit, CDK, or a Rust layout core)
  produces better coordinates for crowded structures.
- A domain-specific arrangement (crystal packing, polymer repeat
  units) needs placement rules the built-in placer does not know.

Assigning `Layout.backend` is process-global; tests and servers that
swap it should restore the default (`Layout.backend = nil`).

The model, the formatters, and the wire form are unchanged by a
backend swap — which is the point: depictions are views.
