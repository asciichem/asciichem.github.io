AsciiChem is a **contract**, not a codebase. The contract has two
halves: the [wire form](/models/) (asciichem-model — versioned JSON
Schemas plus generated types) and the [conformance corpus](/models/#conformance)
(asciichem-tests — the fixtures every implementation must pass in its
own CI). Anything that passes both *is* AsciiChem.

This is the single-contract rule: there is no "the parser". There is
the reference implementation and its equals.

## Picking an implementation

- **Documents and standards pipelines (Ruby)** — the gem integrates
  with Metanorma-style publishing; CML round-trip for interchange;
  the CLI covers parsing, rendering, linting, resolving, validation.
- **Web and interactive tools (TypeScript)** — parse and draw
  chemistry client-side; the corpus guarantees the same acceptance as
  the reference, so your web previews match your build-time renders.
- **Data and science workflows (Python)** — zero-dependency parsing
  into plain dataclasses; wire JSON in and out for pipelines.

All three speak the same wire form, so structures move freely between
ecosystems.
