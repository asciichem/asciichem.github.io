[asciichem-rs](https://github.com/asciichem/asciichem-rs) is the Rust
implementation. It follows the same single-contract rule as the other
three, but takes the grammar a different way: **it does not
reimplement the syntax.** It consumes the compiled PARG artifact of
the AsciiChem grammar and runs it on
[parsanol](https://github.com/parsanol/parsanol-rs)'s portable engine.

```sh
cargo add asciichem     # not yet published — build from source
cargo test              # corpus-backed, see below
```

## What PARG means here

PARG is the compiled, checksummed form of the grammar language —
one compiler (Ruby-side), N consumers. The crate vendors the artifact
(`artifacts/asciichem.json`, the same one the Ruby `:parg` engine
runs) and `parsanol` verifies the envelope checksum at load. A stale
or tampered artifact fails loudly instead of parsing a different
language.

```rust
asciichem::parse("2H_2 + O_2 -> 2H_2O")?;        // Ok when fully captured
asciichem::parse("C1CCC")?;                       // Err — unclosed ring
asciichem::parse_to_text("2H_2 + O_2 -> 2H_2O")?; // canonical text, == input
asciichem::mathml::render("^14C")?;               // byte-exact presentation MathML
```

Two behaviours worth knowing:

- **Short captures are errors.** Parsing must consume the whole
  trimmed input; a grammar edit that leaves a trailing literal
  uncaptured is rejected, not silently ignored.
- **Deep nesting runs on a dedicated large-stack thread.** The
  recursive PEG engine overflows a default thread stack on the fuzz
  corpus's deeply nested inputs; `parse` reserves a stack that is
  committed only as used.

## Conformance claim

The Rust implementation claims the **parse contract** and the **L1
text round-trip contract** — every corpus case parses or rejects
exactly as marked, and every round-trip fixture renders back through
the canonical text form byte-identically, gated in CI:

| Level | Claim |
|---|---|
| parse/reject | 100% — every corpus case parses or rejects exactly as marked |
| L1 (text round-trip) | 100% — every round-trip fixture satisfies `parse_to_text(s) == s` |
| L2 (MathML goldens) | 100% — every corpus MathML golden renders byte-exactly |
| L0 (wire form), L2 (SVG) | not yet claimed — the next slices |

The MathML renderer mirrors the reference formatter rule for rule —
isotopes as `mmultiscripts` left superscripts (the atom-binding fix,
never a phantom base), `msubsup` for subscript + charge/oxidation,
conditions as `mover`/`munder`/`munderover` — byte-exact with the L2
goldens.

The semantic model subset mirrors the reference implementation's
`TransformRules`: atoms with isotopes, charges, oxidation states, Lewis
markers, ring closures and chirality; all bond kinds; groups across
bracket kinds; molecules with coefficients, stereo and `@`-annotations;
reactions with all four arrows and bracket conditions; cascades;
electron configurations; mechanisms with electron-flow flows and
spectators; quoted text; embedded math. Constructs outside the subset
report `not yet supported` rather than guessing.

The site's [conformance matrix](/guides/conformance-levels/) reports
this honestly per implementation.

## Roadmap

The remaining slices follow the corpus contract: the SVG renderers,
then the wire form. Because the grammar artifact is shared, the port
is the tree-to-model transform, not the parser.
